# 28cell — 28핀 범용 스캔셀 (예정)

SOP28 / DIP28 ZIF 소켓의 **28핀 전부**를 스캔셀로 덮어서, 핀맵만 바꾸면 어떤 칩이든 같은 테스트 엔진으로
검증하는 것이 목표입니다. 아직 구현 전이며, 이 폴더에는 계획과 참고 자료만 있습니다.

---

## 7cell 과 달라지는 점

| 항목 | 7cell (지금) | 28cell (계획) |
|---|---|---|
| 셀 수 | 7 | 28 (+ 예비 4 = 32, SPI 4바이트) |
| 체인 정의 | `CHAIN` 7개 고정 | 소켓 핀 번호 1~28 순서, 칩마다 **핀맵 파일**로 역할 지정 |
| 핀 역할 | 코드에 고정 (DRIVEN/CAPTURED/BYPASS) | 핀맵의 `in / out / vcc / gnd / nc / clk / rst` |
| SPI 전송 | 벡터당 1바이트 | 벡터당 4바이트 |
| 비트 배치 | `tx_bit()/rx_bit()` 일반식 (N ≤ 8) | N > 8 로 확장 (바이트 경계 포함) |
| 벡터 형식 | `vectors.bin` 1바이트 (입력 4 + 출력 2) | 핀당 `{방향, 마스크, 값}` 의 N바이트 고정 패킷 |
| 전원 핀 | 보드에서 직접 배선 | 점퍼로 레일 연결 + 셀을 같은 레벨로 구동 (충돌 0) |
| 출력 핀 충돌 | 출력 셀 미러 (`output_mirror`) | 같은 방식을 모든 `out` 핀에 적용 |

## 재사용할 것 (7cell 에서 그대로)

- `Scan7` 의 shift / update / capture / clock 구조 → `ScanN` 으로 일반화
- "SHIFT 한 번에 새 벡터 넣기 + 직전 결과 꺼내기" 파이프라인
- bin 별 판정, `compare_log.py` 호환 실측 로그, yield.csv
- `dryrun/` 의 가상 보드 + "정답을 내는 칩" 검증 방식
